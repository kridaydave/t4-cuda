Power Regime Split

The central insight: a passively cooled 70W GPU behaves fundamentally differently from actively cooled datacenter hardware. Launching 100% occupancyOccupancyThe ratio of active warps per SM to the maximum supported warps. On Turing: max 64 warps/SM (2048 threads). 100% = 64 warps, 50% = 32 warps, 25% = 16 warps. The 4-bit → FP16 conversion (dequantization) is traditionally expensive — requiring bit-field extraction and integer-to-float conversion. Signed INT4: The 0x6A Innovation

Standard INT4INT44-bit integer. Can be unsigned (u4, range 0–15) or signed two's complement (s4, range -8 to 7). For unsigned, the magic exponent is 0x6400 (low nibble) and 0x6400 (high nibble) → constant 0x64006400. For signed, we must also flip bit 3 (the sign bit). Magic constant becomes 0x64086408 with LUT 0x6A to invert bit 3. dequantization (0xEA) is well-established in ExLlamaV2, Marlin, and AWQ. Our signed INT4 extension uses LUT 0x6A with magic constant 0x64086408, which inverts bit 3 (the sign bit) and inserts the exponent simultaneously — everything in one SASS cycle.

0x64006400 LUT: 0xEA = (A & B) | C Signed variant: 0x64086408 + LUT 0x6A (inverts bit 3 = sign)
Single-cycle LOP3 magic number insertion bypasses the integer-to-float pipeline. The nibble bits become FP16 mantissa bits directly.

Shared Memory Bank Conflicts

The T4 has 32 shared memoryShared Memory (SMEM)A software-managed cache within each SM. On T4 with cudaFuncCachePreferL1, the unified 96 KB L1/SMEM is split as 64 KB L1 + 32 KB SMEM. SMEM is divided into 32 banks (4 bytes each). Accessing the same bank from different threads in the same warp causes a serialization penalty (bank conflict). banks (4 bytes each). ldmatrix — the Tensor Core matrix load instruction — requires XOR-based swizzle patterns to avoid 32-way bank conflicts that would otherwise serialize all accesses.

Execution & Verification Protocol

The analytical models presented here require empirical validation on physical T4 hardware. Below is the staged verification pipeline.

  1. Static Compile Check — nvcc -arch=sm_75 -Xptxas -v to verify register counts (target ≤64 regs/thread) and zero stack spills.
  2. PyTorch Extension Build — python3 setup.py build_ext --inplace to verify C++/CUDA linkage, PyBind11 signatures, ABI compatibility.
  3. KAT Vector Verification — Known Answer Test: run kernel on hex vectors 0xA7C13E59, 0xF817E29A, compare against PyTorch reference. Must match with atol=1e-3.
  4. Hardware Telemetry — nvidia-smi --query-gpu=clocks.sm,power.draw,clocks_throttle_reasons.active at 20ms intervals under sustained kernel execution. Verify clock locks at 1590 MHz under 25% occupancy.
  5. Nsight Compute Profiling — ncu --metrics sm__throughput... to measure DRAM SOL%, Tensor Core pipe utilization, and warp stall causes.
